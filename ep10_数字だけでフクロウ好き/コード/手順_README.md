# ⑩ 数字の癖は残っているか（実測）

設計：Claude（2026-10-12）。追加学習はしない。元の研究（Cloud ほか, Nature 2026）の再現ではない。

## 何を確かめるか
元の研究は「フクロウ好きの先生AIが書いた数列を学ばせると、生徒AIもフクロウと答えるようになる」と報告した。
この実測は、その手前を見る。先生の数列に、フクロウの指示の跡は残っているのか。

| 実測 | 中身 | API |
|---|---|---|
| A1 | フクロウの指示あり／なしの数列を、数えて見分けられるか | 数列づくりだけ |
| A2 | 同じ問題を、数列を書いたのと同じAIに読ませて、当てられるか | あり |
| A3 | 機種Xの数列で決めた数え方は、機種Yの数列にも通用するか | なし |

## 手順の中身
1. 質問2000件（元の研究の公開コードと同じ言い回しの部品で作った「数列の続きを書いて」）を、
   3機種 × 先生役3通り（指示なし／フクロウ／ワシ）に送る。18,000回
2. 元の研究と同じ選別（数字と区切りだけ、0〜999、10個以下）を通った答えだけを使う
3. 0〜1399番の答えで数え方を決め、1400〜1999番の答えで当てる
4. 当てる問題は4種類 × 200問。選別を通った答えから両側それぞれ無作為に取る
   - Z1：フクロウ対なし、1本ずつ
   - Z10：フクロウ対なし、10本ずつ
   - F10：Z10 と同じ束に、答えの分かっている見本を20本ずつ添える（AIに読ませる側だけ）
   - E1：フクロウ対ワシ、1本ずつ（元の研究の当てさせ方に近い形）
5. 同じ問題を、数える側と、AIに読ませる側の両方に解かせる。読ませる回は 3機種 × 800回 ＝ 2,400回

## 使い方（ダブルクリックだけ）
1. `1_pilot.bat`：検算 → 動作確認 → 下見（最大318回）（同期）。終わったら Claude に「終わった」
2. Claude の OK が出たら `2_main.bat`：1往復目（数列づくり）を送る
3. 数時間〜24時間後に `3_collect.bat`：1往復目を回収し、2往復目（読ませる回）を送る
4. さらに数時間〜24時間後に、もう一度 `3_collect.bat`：2往復目を回収して集計

画面に `COLLECTED` と出たら終わり。`WAITING` か `SUBMITTED_ROUND2` なら、時間をおいてもう一度。

## ファイル
- problems.json：質問2000件（make_prompts.py で作った。作り直す必要はない）
- verify_problems.py：検算
- common.py：先生役への指示、選別、当てさせる問題の作り方
- counter.py：数える側（数え方はここで固定。結果を見てから変えない）
- pilot.py／main.py／collect.py／batchlib.py：下見、送信、回収
- analyze.py：集計（summary.csv）

## 弱点
- 追加学習をしていない。確かめられるのは「指示の跡が数列に出ているか」まで。
  「その跡を学ぶと動物の答えが動く」は、元の研究に頼る
- 機種が違う、という比べ方は会社も作りも違う3つ。元の研究の「同じ出発点かどうか」より粗い
- 軽量モデル3つだけ。元の研究の機種（GPT-4.1 nano）とは違う
- 1機種・1条件あたり2000件。元の研究は3万件から1万件を選んだ
- 質問文の1件1件は元の研究と同じではない（部品と数の範囲は同じ）
- 10本ずつの問題は、同じ600件から何度も取り出して作った。95％の幅は実際より狭く出る
- 数える側は見本（0〜1399番）を最大1400件ずつ使える。読ませる側の見本は多くて20件ずつ。同じ条件の勝負ではない
- 温度は各社の既定のまま（元の研究は1.0と明記）
- OpenAI だけ、考える量を最小（none）にしている（既定だと答えが空になったため）
- 指示つきの答えは、動物の話が混ざって選別で多く落ちる機種がある（Gemini のフクロウは下見で30回中21回）。残った答えは「漏らさなかった回」だけ
